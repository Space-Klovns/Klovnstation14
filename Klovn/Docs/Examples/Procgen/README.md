## Scoped utility intent

Request schema 2 adds an optional `utilities` object (nested schema 1). This is authoring data;
the composed planners currently return `UtilityPlanningUnsupported` for any nonempty contract.
The following example can be captured and transported, but cannot yet generate powered rooms:

```yaml
schemaVersion: 2
requestId: ScopedOffice
shape:
  cells: ["0,0", "1,0", "2,0"]
utilities:
  schemaVersion: 1
  gasAssignments:
  - id: AreaAir
    scope: Area
    profileId: KsProcgenStandardAir
  consumers:
  - id: Computers
    scope: Area
    selector: Prototype
    selectorId: ComputerAlert
    circuitId: Main
    requirement: Required
    supply: Operational
    minimumMatches: 1
  gasRestrictions:
    allowedGases: [Oxygen, Nitrogen]
    maximumPressureKPa: 120
  electricalRestrictions:
    forbidBatteryOnly: true
```

Use `KsProcgenRequestSnapshot.TryCapture(manager, request, ..., draft: draft)` to resolve named
gas profiles from loaded content or a validated local draft. The snapshot carries complete inline
gas bodies and source IDs; its copies can subsequently be captured without consulting prototypes.
`scopeId` is omitted for `Request`, defaults to the request ID for `Area`, and is mandatory for
`Room`/`GasDomain`. Room/domain/member IDs refer to planned objects and still require candidate
binding; successful capture does not prove they exist. Prototype selectors are checked at loaded
capture; they do not prove receiver eligibility or a matching placed device. Null nominal/peak
watts mean inspection is required, never zero demand.

`gasWriteCells`, `cableWriteCells` and `deviceWriteCells` can independently narrow the request's
normalized writable cells. Omission inherits ownership; an empty list forbids all writes on that
layer. These masks cannot grant access to preserved content, constants, voids or unowned cells.
Request-hard restrictions remain constraints to evaluate after effective profile and live-context
resolution. Capture supplies no gas isolation, power topology, operational supply or publication
certificate. Schema 1 rejects `utilities` instead of silently accepting an unsupported extension.

## Atmosphere profile inspection

The 2026-10-15 atmosphere foundation loads `KsProcgenStandardAir`, `KsProcgenNitrogenRoom`,
`KsProcgenVacuum` and `KsProcgenPreserveAtmosphere`. An opt-in `KsProcgenNitrogenOfficeArea`
paint profile and `KsProcgenNitrogenOfficeTheme` demonstrate references. Existing office areas
retain their previous defaults. Resolving a profile authors gas requirements; the owned runtime
adapter described below performs the actual fill.

`KsProcgenAtmosphereProfiles.TryResolve` returns a detached immutable profile with named gas
fractions, pressure, temperature and versioned identity. `CopySpec()` returns editable independent
data. `TryResolveSelection` applies an inline override, then an explicit profile, then a supplied
resolved default; it never merges individual gases across those levels.

`KsProcgenAtmosphereMixturePlanner.TryPlan(profile, actualTileVolume, out mixture, out issue)`
calculates one tile's amounts and checks actual `GasMixture` pressure arithmetic. Use the actual
tile mixture's volume. It returns detached data; preserve mode cannot create a fill proposal.
No result certifies live gas initialization or atmosphere stability.

Area snapshots now use semantic version v7 and area-review JSON schema 3, including resolved
atmosphere data. Owned geometry-report JSON/SVG samples remain schema 1. A painted blob's
`CreateRequest` transports a fresh inline gas spec, so later prototype edits cannot change its
earlier snapshot. Direct requests may select `atmosphereProfile` or an inline `atmosphere` override.
The server `KsProcgenPlanningSystem.Propose` captures retained airtight declarations and binds
gas demands to complete candidates. Shared planning requires the matching immutable gas context;
legacy entries without it still refuse explicit gas contracts. Theme gas defaults are checked
before packing, including plans that would never select procedural room contents.

`KsProcgenOwnedStageSystem.TryGenerate` accepts the supported owned gas plan. Call `TryInitialize`
on its returned stage to inspect actual gas-bearing tiles and cardinal boundaries, fill independent
mixtures using actual tile volume, and commit `InitialAtmosphere` only after lifecycle checks.
Required fills reject leaking domains. Optional leaking or numerically unrepresentable fills are
omitted for the entire domain; receipt omissions explain the result. Hard utility bounds always
remain mandatory. `RequiredInitialGasVerified` describes hard initial success; `InitialGasVerified`
additionally covers preferred initial values. Optional unsupported stability has its own omission;
`AtmosphereAtRestVerified` remains false. Required stability/observation intervals and hosted or
preserved gas context remain unsupported. Repeat initialization and `Verify` never refill gas or
rewrite the historical receipt. Discard the owned stage after review; this does not authorize
publication, stable simulation or operational power.

## Electrical profile inspection

The electrical foundation loads `KsProcgenAutomaticElectrical`, `KsProcgenWiredElectrical`,
`KsProcgenExistingElectrical` and `KsProcgenDisabledElectrical`. Opt-in powered office area/theme
examples reference the automatic profile. These are authoring presets; they do not generate wires
or an energy source. An operational request still needs independently inspected source interfaces.

`KsProcgenElectricalProfiles.TryResolve` creates an immutable snapshot; `CopySpec` returns fresh
editable converter choices, interfaces and circuit lists. Inline `electrical` overrides replace
the entire selected `electricalProfile`, including its interfaces. A source interface declares a
cell, voltage, stable network/circuit key, available watts and connection intent; it never grants
write permission or proves capacity. Current policy fields include demand margin, startup and
observation ticks, battery-only permission, optional initial charge and cable reuse.

The server's `KsProcgenElectricalCapabilityInspector.TryInspect` reads real inherited prototype
components without spawning entities. It checks cable tiers and converter connectors, and reports
LV range and finite battery/supply/breaker declarations. Both verification flags remain false:
static capability does not establish mounting, actual node membership or power under load.

`KsProcgenElectricalReach.WithinRange` checks the engine's inclusive geometric radius using supplied
actual ranges. The standard cable's default is 3 world units (29 tile centers on the unit grid),
including (3,0) and (2,2) and excluding (3,1). It does not check walls, grid identity, anchoring,
provider competition or supplied watts. Both main content planners currently refuse explicit
electrical contracts rather than drop them from their output.

## Captured planning projects and geometry libraries

`KsProcgenProjectSpec` schema 1 binds named `areas` to `request`, `theme`, and optional `library`.
Each area key must equal its request ID. Procedural areas omit libraries; prefab/hybrid areas name
one explicitly. Optional `content`, `utilities`, and `layouts` documents must have the project's
document ID and current revision. Missing interior/utility documents start empty. Project capture
imports referenced loaded theme inheritance/fallback, material/light/entity packs, assemblies and
utility definitions into detached authoring data, so those definitions travel with `CopySpec()`.
It also pins complete utility overrides in every canonical request.

`KsProcgenLayoutDraftSpec` schema 2 contains `rooms`, `families`, and `libraries`. Schema 1 is
accepted with the original source-coordinate defaults and normalized to schema 2. Room assets
declare exact `cells`, `exteriorFacades`, `ports`, and optional paired `sourceKey`/
`contentFingerprint` expectations. A family's options each declare `reservationCells`,
`generateCells`, and locally transformed `members` (`id`, `room`, `origin`, `quarterTurns`). Every
option must partition the same reservation exactly. Room members cannot be combined across options.
The existing fitter chooses global origins and permitted family quarter turns automatically.

For a room in a source atlas, set optional `sourceGridUid` to the positive map-local grid YAML UID
and `sourceOrigin` to the native tile corresponding to room-local `(0, 0)`. A declared room cell
`c` selects native tile `c + sourceOrigin`. Cells, port thresholds, facades and fitted family
members remain room-local. For example, `sourceGridUid: 17` and `sourceOrigin: 40,-12` extract
room-local `(0,0)` from native `(40,-12)` on grid 17. Negative origins are supported; origins and
translated cells must remain within +/-1,000,000 on both axes. These fields require a source
key/fingerprint pair and layout schema 2. Omit the grid selector only when one occupied unit
grid matches unambiguously. Explicit selectors never fall back to another grid. Source extraction
returns both native `GridPosition` and rebased `RoomPosition`, preserving parent-local poses.
It remains a static witness; component-reference closure and copying are not yet authorized.

A library lists family names and/or individual room references with `allowedQuarterTurns`.
Individual rooms compile into singleton `Room/<asset>` families. Layout asset, option, member and
port IDs omit `/` to reserve
that namespace; source keys remain opaque authoring identifiers and may contain `/`. They are not
client-controlled filesystem destinations. Port thresholds, inward cells and outward cardinal
normals must satisfy the existing room geometry validator, including after local transforms.

Capture projects with `KsProcgenProject.TryCapture(manager, editable, out project, out issue)`.
`TryArea` returns a canonical request, captured theme catalog and optional compiled library. Pass
these to the existing geometry pipeline:

```csharp
var area = project.Areas[0];
var result = KsProcgenGeometryPipeline.Plan(manager, area.Request.CopyRequest(),
    area.Library?.Families ?? [], area.Content.Theme.Id, content: area.Content);
```

The project retains source-room bindings by family/option/member for later map adapters. Source
fingerprints are declared expectations; capture does not inspect or copy actual room maps. A
`GeometryPlanned` result is a preview, with the existing access, source and engine limitations.
Disconnected room networks and unsupported utilities remain failures. In particular, this does
not enable the primary owned planner's pending hybrid path or waive the existing stage guards.

`CopySpec` returns independent project/asset/request bodies; receiving engine serialization can
roundtrip them. `TryRevise` checks project identity and current revision, captures the replacement
atomically, then increments the project and all serialized child revisions once. Failed/stale
replacement returns no project. It does not provide a server writer lease, permissions, undo,
storage or UI. Project identity excludes document/revision metadata and includes retained area
requests, selected catalogs and authored asset bodies. It is not a complete replay manifest:
entity components, tile definitions, actual room-map contents and live host facts still need one.

Limits include 64 areas, 256 combined project assets, 65,536 cumulative normalized target/envelope/
void mask cells, and each child document's limits. Layout drafts additionally bound cumulative
source masks and expanded room instances to 65,536 cells each, 32,768 collection elements and 256
assets. Advanced layout void/seam/link rules, eligibility and map capture remain open tasks.

## Detached interior asset drafts

`KsProcgenContentDraftSpec` schema 1 contains `documentId`, `revision`, and dictionaries named
`themes`, `tiles`, `walls`, `lights`, `entities`, `assemblies`. Values use the same explicit
authoring fields as loaded prototypes, without their global `id` or `type` fields. Dictionary keys
are asset names; the same name may be used in different kinds. Draft assets shadow loaded assets
only during explicitly scoped capture. A theme can inherit a loaded parent and override one pack.

```csharp
var editable = new KsProcgenContentDraftSpec
{
    DocumentId = "MyInteriors",
    Themes = new() { ["LocalOffice"] = new()
    {
        Parent = "KsProcgenSimpleOffice",
        TilePacks = new() { new() { Pack = "LocalTiles" } },
    } },
    Tiles = new() { ["LocalTiles"] = new()
    {
        Palettes = new() { new() { Id = "Steel", PrimaryTile = "FloorSteelMini" } },
    } },
};
if (!KsProcgenContentDraft.TrySnapshot(editable, out var interiors, out var issue))
    return;
if (!KsProcgenThemeCatalog.TryCapture(manager, "LocalOffice", out var catalog, out issue,
        assets: interiors))
    return;
// Supply catalog as content: catalog to the existing owned planner.
```

`TrySnapshot` deep-copies a bounded authoring revision. Broken references may remain in a draft for
editing; capture validates the selected theme's complete candidate pools and relational variants
before planning. An invalid local override fails capture and does not silently use the loaded
asset with that name. `draft: utilityDraft` can be supplied alongside `assets: interiors` to resolve
local utility defaults. Neither operation registers prototypes, spawns entities or certifies utility
operation. A successful catalog retains copied data after source edits or draft replacement.

`CopySpec()` returns independent editable data. `TryRevise` accepts a full replacement with this
document ID and current revision, validates structure and advances the revision once. It is a value
operation; the eventual server document owner must serialize concurrent replacement and enforce
permissions. Declaration identity excludes document ID/revision, sorts dictionaries, and retains
ordered authoring lists, including complete assembly alternatives. This is authoring identity,
distinct from the theme catalog's canonical planning identity and a complete content manifest.

Limits: 128 assets combined, 32,768 cumulative collection elements, 1,048,576 string characters,
512 characters per string, plus per-kind/member/relation limits. Null bodies, unsupported enum
values, nonfinite numbers and oversized structures are rejected with no partial draft. Room maps,
libraries, layout-family authoring, assignments, dependency manifests, persistence and UI are still
separate open tasks. The legacy utility draft remains its own schema and retains its validation.

## Captured theme candidate pools

`KsProcgenThemeCatalog.TryCapture(manager, themeId, out catalog, out issue)` captures the resolved
theme's complete current material/light/entity candidate pools and compatible tag sets before any
per-room choice. `DeclarationHash` includes unselected alternatives, weights, core minima, complete
assembly relations/geometry and authored variant priority. Unordered pools/tags have canonical
identity. The catalog has schema version 1 and is an in-memory planning declaration snapshot.

`KsProcgenThemeSelector.TrySelect(catalog, seed, roomId, out choice, out issue)` uses no prototype
lookup. Pass `content: catalog` to the owned planner's `PlanSnapshot` to keep these pools across
retries and later source edits. Omitting it captures current content once for that planning call.
Owned results expose `ContentDeclarationHash` alongside output `SemanticHash`. These distinguish
planning declarations and output identity; neither alone certifies the complete live runtime/context.

This is not a complete runtime content/context certificate or portable replay artifact. Entity
components, static capability snapshots, room libraries/fallback eligibility and inspected host
facts still need wider capture. Gas defaults now participate in supported owned candidate bindings;
electricity and missing hosted/preserved gas context retain unsupported-planning guards.

## Retained selected content

Selections returned by `KsProcgenThemeSelector` retain `Content`: detached chosen material/light
declarations, theme goals and compiled entity cores. Material, hull/window, furnishing and lighting
planning uses that retained data. Editing a source prototype later changes a new selection, while
the earlier one keeps its previous planning choices. Changing a selected material/fixture/pack ID
without matching captured content is rejected instead of silently combining the old body with it.

Manually constructed selections with `Content == null` retain the legacy reference-based path;
tests that deliberately author new reference inputs clear captured content explicitly. This is
not an editor upload format or full content manifest. Entity component bodies, inspected scene
context and pack-only supported-room previews still need wider capture.

## Canonical request snapshots

`KsProcgenRequest` defaults to schema version 1; unsupported versions are rejected before planning.
`KsProcgenRequestSnapshot.TryCapture` normalizes masks, constants, entrance configurations and
nested goals into detached canonical data with a stable `DeclarationHash`. `CopyRequest()` returns
fresh editable data for engine serialization. The prototype-aware overload resolves named utility
profiles, optionally using `draft:`, then pins full inline declarations with their provenance.
Earlier utility choices survive subsequent profile edits. Headless capture requires inline data
for any named utility and can recapture a serialized snapshot without its original draft catalog.

`KsProcgenOwnedInteriorPlanner.PlanSnapshot` consumes retained request data. It still needs content,
budgets and inspected host context from the caller and retains all unsupported utility/publication
guards. Request identity is not a full content manifest, host-context certificate or replay receipt.

## Utility authoring drafts

`KsProcgenUtilityDraftSpec` is the version-1 headless utility asset document: `documentId`,
`revision`, and dictionaries named `atmosphere` and `electrical`, keyed by local asset name.
`KsProcgenUtilityDraft.TrySnapshot` validates all assets against receiving-content gas/entity
callbacks and freezes them. The combined asset limit is 128. `CopySpec()` returns an independent
editable document; `TryRevise` requires its original document ID/revision and returns the next
immutable revision after validation. The owner must serialize replacement of its current revision.

Pass the resulting catalog using the optional named `draft:` argument to utility `TryResolve`,
`TryResolveSelection`, or theme `TryResolve`. Inline utility data takes precedence; explicit names
look in the selected draft before loaded prototypes; inherited defaults remain last. No global
prototype is registered or edited. Keep document identity and revision alongside `ContentHash`,
which identifies utility declarations only. A future loaded-content manifest is still required.

This is an internal authoring foundation. There is no draft UI, network upload, persistence,
writer lease, operation deduplication or map assignment support yet. Current production planners
refuse unsupported power/hosted-gas contracts. Supported owned gas contracts use candidate bindings
and the initialization receipt described above.

## Preview map ownership and cleanup

Tile, surface, container and assembly previews now retain their stage data through a server-only
`KsProcgenStageSessionComponent` on the owned map. `KsProcgenStageOwnershipSystem` queries these
components, including paused maps; there are no separate persistent map dictionaries in the four
stage systems. Existing typed stage handles and initialization methods remain available.

Each kind retains at most 16 maps, with 64 total across the four kinds. Tile staging now has the
same retention cap and preview-operation interlock. A failed retention check occurs before map
allocation. Kind-specific `DiscardAll` leaves other preview kinds intact.

External map deletion retires its handle and cleans recorded owned members even if they escaped
to another map. A later public discard returns false for that retired handle. Reusing a numeric
map ID does not transfer ownership: the map entity UID and component's exact handle must match.
Ownership removal or queued deletion during initialization rejects the result; late captured
allocations are cleaned before return. The ownership component/handle data is not a writer lease
or an authorization for client-provided entity references.

`KsProcgenPreviewOperationSystem` captures allocations for all five kinds, including tile callbacks.
Tile previews count cumulative allocations, including immediately deleted entities, and reject
unexpected live callback entities. Their allocation bound includes the map and grid; cancellation
or failure cleans recorded entities even when callbacks placed them outside the map.

Room fixture inspection follows the engine's map transform tree, including paused, noncollidable
and contained descendants. Unrelated maps consume no room scan budget. Foreign entities are
rejected even when nested below an owned member or container; the captured allocation list alone
does not establish complete scene membership.

Surface, container and assembly initialization delegates to `KsProcgenStageLifecycleSystem`.
The common handle exposes uninitialized/initializing/initialized/retired lifecycle state; existing
per-kind phase properties are read-only projections. One transaction handles paused initialization,
capture, pre/post content checks, cancellation, idempotence and failed-stage release.

This rewrite does not establish operational, visibility, atmos or power isolation. Complete
standalone owned proposals now materialize through `KsProcgenOwnedStageSystem`; hosted/hybrid
materialization, derived whole-plan limits and broader session lifecycle remain R10 work.
Pausing and deleting a preview map is not general rollback of initialization's global side effects.

## Clockwise authoring and engine placement

Author quarter-turns are clockwise from the down/south baseline: `0` down, `1` left, `2` up,
`3` right. Native engine angles are counter-clockwise. Use `KsProcgenRotation.ToEngineAngle`
at the placement boundary; author turn one becomes engine minus 90 degrees. The surface,
assembly and complete owned adapters use the same conversion for placement and verification.
Directional gas nomination uses it too. Pure footprint/approach geometry stays clockwise.

Source-map extraction's `LocalRotationRadians` and `GridRotationRadians` already contain native
radians; keep those native when composing source hierarchies. Do not treat them as author turns
or negate them a second time. Support-pose identity is now v2, owned interior identity v3 and
gas-context identity v2; older hashes identify older meanings. Historical diagnostic examples
are review projections, not a promise to replay under these new identities.

The default four-direction sprite mapping agrees with the native computer-facing regression.
Custom sprite direction offsets/overrides and operational interaction still require their own
calibration; a correct transform or a visible arrow is not full machine-use certification.

## Owned layered furnishing proposals

For standalone owned planning, set `request.EntranceDomain = new()` with empty entrances and
configurations. `PerIsland` derives rooted networks independently for each target island;
`SingleNetwork` requires all roots together. Explicit request roots remain required terminals.
`DeclaredNetworks` requires explicit configurations; groups may use roots without any ports.
No outside host tiles or fake thresholds are needed. Null entrance domains retain legacy behavior.
Canonical request snapshots store the resolved defaults, while the original request stays editable.

`KsProcgenPlanningSystem.Propose` is the server entry to the existing owned planner with static
component inspection supplied. It accepts the same request, theme/catalog, route context and
exterior facts. In shared code, supply `componentFactory:` to `KsProcgenOwnedInteriorPlanner.Plan`
or `PlanSnapshot`. Floor-only selected content keeps its existing path. Selected surface/container
relations use whole-core supported search inside each owned layout/configuration attempt.

A successful room's `Proposal.Layered` retains its complete assembly, source bindings, static
capabilities, poses, footprint/access witnesses and floor projections. `Proposal.Entities` contains
floor roots only. Surface items keep their support poses; contained items retain coordinate parents
and are not floor occupants. Never materialize a layered result by flattening its members into the
legacy entity list. Legacy tile staging rejects layered content; the complete owned stage now
materializes supported standalone proposals. Hosted/hybrid staging, operation and publication
remain open integration gates.

Required core copies cannot be silently dropped. Rejected optional instances can be removed as
whole units with sparse-furnishing diagnostics; denied sparse fallback still rejects the candidate.
Variant, placement and landing probes share the owned furnishing allowance, including final-audit
landing probes. All graph expansions remain charged across retries. Budget failure exposes no
partial furnishing artifacts. Advanced density/optional-member policies and general read-only edge
placement remain pending; the existing whole-variant search bounds still apply.

Lighting reserves exposed occupied cells, operating approaches and clean operating paths. The final
independent audit requires the current structure, checks floor projections against the layered
witness, recomputes supported access, and audits whole-room/entrance connectivity after lighting.
Vault-required furniture still blocks clean walking. None of these static planning checks certify
initialized collision, anchoring, device/chair use, actual light emission, gas, power or publication.
Existing diagnostic JSON/SVG is still a floor projection and needs a layered export extension.

## Owned room scene inspection

The server room-core adapter accepts `floorTileId: "FloorSteel"` on `TrySearchRoomStage` to
allocate its declared floor/wall masks on a disposable grid. Use a room mask whose
`CellCenterOrigin` is `(0.5, 0.5)` and provide a registered wall prototype when changing the
default `WallSolid`. The caller must retain and discard the returned owned stage. Existing
support/container previews are available; spatial-relation staging remains gated.

After successful `TryInitialize`, call `KsProcgenRoomFixtureSystem.Check(stage)` for fresh
member/member and member/wall hard-fixture overlap inspection. Declared wall/wall joins form
a permitted structural union. Then `CheckCardinalAccess(stage, actorUid, root, terminals)`
can inspect continuous cardinal clearance for the live external actor's hard fixtures at its
current fixed orientation. The actor is read without moving it; vault-required and normally
blocking content is excluded, and the full swept bounds conservatively require floor.
Changed terrain, unsupported shapes, foreign scene entities and work exhaustion reject the
inspection without returning a partial connectivity witness.

These observations never approve publication or operational room use. Joint/event rules,
physics settling, door opening, machine/chair operation, gas closure, supply and working lights
still need their own engine gates. Reports expose the work consumed and leave
`engineAccessVerified` and `published` false.

## Owned electrical planning

Set `ElectricalProfile` to `KsProcgenWiredElectrical` on a standalone footprint request, then use
`KsProcgenPlanningSystem.Propose`. Utility contracts require `SchemaVersion = 2`. A complete
candidate carries `Electrical` with proposed converter poses, cable cells by voltage, consumer
coverage, retained load declarations and explicit omissions. This is planning output.

Converters are mandatory infrastructure members in the same room search as authored furnishings.
Their typed origin keeps them separate from authored packs named `Electrical` or cores named
`Apc`/`Substation`. The planner tries utility home rooms in descending floor-area order, then stable
room-ID order, charging each complete retry to the existing layout and work allowances.

The current path supports `AutoDistribute`, shared `Main`, `WiredOnly`, and no existing source
interfaces. Each owned network gets a substation and APC. HV is reserved below substations;
MV connects their same-tile inputs/outputs to APCs; LV extends from APCs to proposed receiver
coverage using cardinal cable steps. The loaded default LV transfer radius is **3 tiles**; the
predicate uses the smaller provider/receiver radius with inclusive Euclidean distance, not a
square neighborhood. Physical provider assignment still requires native inspection.

`CableWriteCells` and `DeviceWriteCells` narrow request write permission. Null inherits permission;
an empty mask permits no writes. Converter footprint placement currently requires both masks;
no mask grants access outside the request. Request/area/room consumers support all-powered,
prototype and fully qualified member selectors with minima. Overlapping selectors produce one
physical consumer proposal; conflicting load declarations reject. Unspecified loads remain
nullable. Required misses reject the whole candidate; preferred misses appear in omissions.
Implicit powered consumers receive best-effort wiring with explicit omissions for unsupported
layers/receivers or unreachable coverage. Use explicit required selectors to require coverage.

Operational supply, hard source restrictions, independent circuits, gas-domain consumer selectors,
and host interfaces remain guarded. Planning-only diagnostics leave `ElectricalTopologyVerified`
and `ElectricalSupplyVerified` false. The complete owned stage now materializes standalone shared
`Main`/`WiredOnly` candidates, verifies native cable/converter node groups and receiver/provider
membership, and retains initial topology evidence. APCs require solid walls; converter palettes
may offer floor and wall substations. This verifies topology, without certifying operating supply
or post-load wiring. Combined gas candidates additionally undergo owned initial-fill validation.
