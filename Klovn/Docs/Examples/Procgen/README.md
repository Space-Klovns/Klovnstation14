# Procgen review artifacts

[L-shaped proposed interior](l-shape.svg) and [its canonical diagnostic report](l-shape.json) are
generated by the loaded `KsProcgenDiagnosticExportTests` fixture. The 28-cell painted shape has
its upper-right 2x2 corner absent. It requests 16- and 9-cell final interiors, with three dividing
wall tiles and one proposed cardinal door. These are proposals; engine access, gas closure,
working lighting and publication remain unverified.

SVG colors: dark walls, colored room floors, blue door thresholds, orange declared entrances,
green protected paths, purple preserved cells, and brown proposed furnishings/approaches. Facing
arrows follow 0/90/180/270 degree turns. Anything declared to block movement or require vaulting
is excluded from clean-passage planning; labels retain the declared movement class.

Regenerate the samples by setting `KS_PROCGEN_ARTIFACT_DIR` to this directory and running the
loaded diagnostic export fixture. The test writes samples only when that variable is explicitly
set. JSON has a versioned schema, deterministic order and separate metadata/geometry truncation
flags. Exact replay verification compares it with a freshly built canonical report; this is not
a content fingerprint or permission to materialize a map.

Server administrators with Debug permission can run
`ksprocgen_snapshot <grid entity> <stable host key>` to inspect connected paint blobs, profile
goals and entrance configurations as bounded JSON. It does not generate, remove markers, infer
verified live doorway context, or publish a map.

## Owned room scene inspection

The server room-core adapter accepts `floorTileId: "FloorSteel"` on `TrySearchRoomStage` to
allocate its declared floor/wall masks on a disposable grid. Use a room mask whose
`CellCenterOrigin` is `(0.5, 0.5)` and provide a registered wall prototype when changing the
default `WallSolid`. The caller must retain and discard the returned owned stage. Existing
support/container previews are available; spatial-relation staging remains gated.

After successful `TryInitialize`, call `KsProcgenRoomFixtureSystem.Check(stage)` for fresh
member/member and member/wall hard-fixture overlap inspection. Declared wall/wall joins form
a permitted structural union. Then `CheckCardinalAccess(stage, actorUid, root, terminals)`
can inspect continuous cardinal clearance for the live external actor's hard fixtures at its
current fixed orientation. The actor is read without moving it; vault-required and normally
blocking content is excluded, and the full swept bounds conservatively require floor.
Changed terrain, unsupported shapes, foreign scene entities and work exhaustion reject the
inspection without returning a partial connectivity witness.

These observations never approve publication or operational room use. Joint/event rules,
physics settling, door opening, machine/chair operation, gas closure, supply and working lights
still need their own engine gates. Reports expose the work consumed and leave
`engineAccessVerified` and `published` false.
